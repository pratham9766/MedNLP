# Architecture

The Vite/React frontend calls the FastAPI `/api/v1` service. The API accepts PDF, PNG, and JPEG uploads after checking the configured byte/page limits, MIME declaration, file signature, and parser readability. Images are decoded and bounded by pixel count. Files use random storage keys outside the public tree. SQLite stores users, per-user documents, analysis JSON, review annotations, and audit events. Alembic manages schema upgrades; a complete pre-migration schema is stamped as the initial baseline without rewriting its rows. Persisted queued/processing report states are recovered at startup, while execution uses an in-process thread pool with single-process concurrency limitations.

PDF extraction preserves page numbers and uses PyMuPDF for embedded text. Pages with sparse text and image uploads attempt pytesseract/Tesseract OCR. Missing OCR or OCR failures become visible warnings and `completed_with_warnings` status. Extraction/classification live in `app/nlp`, parsing/retrieval in `app/services.py`, persistence in `app/models.py`, and routing in `app/main.py`.

Entities retain the exact page text span from which they were extracted. Offsets refer to extracted page text, not coordinates on the rendered page. The analysis schema validates offsets against source text. Patient overview statements and differential possibilities reference extracted evidence IDs. Differential support/limiting links are created only for passages explicitly labeled by the report; the rules do not infer medical support relationships. Lab results preserve reported text, parsed values, comparator, unit, reference interval and report flag where available; comparisons are withheld when required inputs are ambiguous. Radiology findings retain section and modality cues. These are deterministic heuristics, not clinical interpretation.

The summary contains bounded source statements with source spans. QA uses lexical passage retrieval and returns source quotations; it is not generative QA. Review corrections preserve the extracted value and add an audit entry; review reopening is recorded separately. The additive structured overview/differential export uses schema version 1.1 at `docs/schemas/export.v1.1.schema.json`; stored version 1.0 analyses remain readable.

CORS origins, upload byte limits, page limits, and an optional Tesseract executable path are configurable. Startup rejects a missing/default or short signing secret. The authenticated original-file endpoint is used by the UI's local PDF viewer; no external viewer service receives document content.
